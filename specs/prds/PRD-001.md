# PRD-001: User Authentication

## Overview

This document outlines the product requirements for the User Authentication system, enabling users to securely register, log in, and manage their sessions.

## Problem Statement

Users need a secure and seamless way to authenticate into the platform. Without proper authentication, user data and platform integrity are at risk.

## Goals

- Provide a secure login and registration experience
- Support session persistence with "Remember Me"
- Protect against brute-force attacks

## User Stories

- As a new user, I want to register with my email and password
- As a returning user, I want to log in securely
- As a user, I want my session to persist if I choose "Remember Me"
- As a user, I want to see a clear error message when my credentials are wrong

## Functional Requirements

### FR-1: Registration
- Users can register with email and password
- Password must be at least 8 characters
- Email must be unique in the system

### FR-2: Login
- Users can log in with email and password
- System validates credentials against stored hashes
- Failed login shows "Invalid email or password" message

### FR-3: Session Management
- Sessions stored in HTTP-only cookies
- Default session duration: 24 hours
- "Remember Me" extends session to 30 days

### FR-4: Rate Limiting
- Max 5 failed login attempts per minute per IP
- Account temporarily locked after 10 consecutive failures

## Non-Functional Requirements

- Password hashing: bcrypt with salt rounds ≥ 12
- Response time: Login API < 500ms (p95)
- Availability: 99.9% uptime

## Out of Scope

- OAuth / Social login (Google, GitHub)
- Two-factor authentication (2FA)
- Password reset flow

## Success Metrics

- Login success rate > 98%
- Zero credential leaks
- < 1% false lockout rate
